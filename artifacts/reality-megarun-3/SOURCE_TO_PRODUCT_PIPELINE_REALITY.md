# Source-to-product pipeline reality

Observed path: retained regulator/report/official-site packet → attributable atomic proposition → review status plus scope/time/source-role → pair classification → deterministic card/ledger projection. No new fetching, native extraction, OCR, vision, model call, promotion, or release occurred.

The existing Builder path remains the proper production path: source bytes and lineage, native PDF extraction, diagnostics, narrow established escalation only when needed, bounded semantic candidates, governance, then projection. Spike 18 exercised only the last portion. It is evidence that the product can preserve meaning once propositions exist; it is not evidence that the upstream pipeline reliably creates them.

The only safe product contract demonstrated is: preserve propositions keyed at least by subject, predicate, scope, valid time, source role and locator; preserve coverage/missingness independently; expose candidate/review status; do not flatten non-comparable measures. Any upstream improvement must report its own acquired-source, page/chunk, failure, abstention and review denominators.
