# Reality Spike 5 — eight-charity anatomy

## Principal token

`REALITY_SPIKE_5_EIGHT_CHARITY_ANATOMY_DISCOVERED`

All 8/8 subjects compiled, with 171 governed observations and 75 explicit missing section cells. This is a read-only experiment over retained material: no S0 mutation, acquisition, provider call, or cost.

## Input inventory and run

Three charities used retained Spike 3 ACNC/AIS packets plus represented filings; four used frozen Phase 5 ACNC and report representations plus experiment-only human-adjudicated records; Smith used the frozen Data ranking AIS row. Every per-subject card contains the detailed family inventory and generated graph/projection. All are historical snapshots, not claims of current freshness. The executed path was retained representation → experimental source descriptor/observation → `EXPERIMENTAL_PRODUCT_OWNER_PROMOTION` → reusable historical `integrated_card` compiler → JSON/Markdown. No report prose was newly interpreted.

## Anatomy findings

ACNC/AIS is doing nearly all visible work. Sections 1, 2, 4, 8, 11 and 20 are robustly generic (8/8); programmes, geography, workforce, finance and funding reach 7/8. The eight wholly empty sections are Participation, Direct service, Governance, Relationships, Ethos, Conduct, Evaluation, and Classification. That is mostly an observation/projection seam gap: retained report material exists for seven subjects, yet no general report-to-observation adapter consumes it. Historical Phase 5 replay appears in four subjects and only reinforces sections 1–3—evidence that bespoke historical machinery is not expanding whole-card coverage.

## Product value audit

For World Vision, Red Cross, Bush and Greenpeace, cards make programme lists, beneficiaries/geography, workforce/size, finance and funding fields navigable in one sectioned surface; Phase 5 history adds provenance but little new donor answer. MSF, Sunrise and Noongar get the same regulator-derived synthesis, with Sunrise/Noongar also carrying establishment date. Smith demonstrates the floor: a rank, status/size and fundraising flags, but no service or financial explanation. Reports do not materially change this replay because their narrative is not consumed; website material does not change it because none was retained. Without semantic enrichment, cards are useful as an auditable orientation layer, but feel like ACNC data reformatted wherever sections 3–5 are simply copied and sections 6–19 are blank.

## Top product weaknesses/gaps

1. No current packet-to-governed adapter. 2. Historical compiler is a runtime dependency. 3. Report text is retained but unconsumed. 4. Governance promotion is experiment-only glue. 5. No generic semantic-to-section bridge. 6. No current readable vNext renderer. 7. Sparse sources collapse cards abruptly. 8. Sections 6/7 lack capacity semantics. 9. Governance/relationships have no common adapter. 10. Ethos/conduct lack bounded routing. 11. Evaluation evidence is not assembled. 12. Multiple phase models must be translated.

## Surprising strengths

1. All eight compile. 2. Explicit missingness survives. 3. Exact structured fields travel across three source shapes. 4. The historical compiler is genuinely generic. 5. ABN join is enough for experimental identity. 6. Programme/geography lists project without NLP. 7. Finance/workforce coverage is broad. 8. The poor Smith card accurately exposes source-shape dependence.

## Scale-to-100

Empirical: structured record adaptation, graph validation, compiling and rendering are straightforward O(N); assigning/missingness reporting is O(N×20). Report semantic extraction, claim mapping, promotion/adjudication and exception review require model/human work; the Phase 5 history shows those paths are separate from direct AIS mapping. Extrapolation: at 100, review queues, phase-translation maintenance, rights/freshness checks and report routing fail before compiler capacity. Fully automatable now: retained structured record ingestion, explicit coverage, graph validation, matrix generation and rendering. Not safely automatable now: report proposition interpretation/promotion and high-risk sections 6/7/9/12/15/16/18.

## Recommended next tranche

Prefer architecture simplification first: create one current retained-representation → governed-observation adapter plus a current renderer around the existing 20-section contract, then run a source ablation on two rich and two sparse records. Only after that should one bounded report semantic route be attached, targeting Section 18 or 15 where the matrix shows an actual product gap.
