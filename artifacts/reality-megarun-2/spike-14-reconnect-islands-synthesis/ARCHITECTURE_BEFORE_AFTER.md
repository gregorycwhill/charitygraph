# Architecture before and after

| Concern | Before: historical path | After: proposition bridge | Conclusion |
|---|---|---|---|
| Knowledge unit | 6+ record families through governed promotion | G2 proposition, evidence ref, coverage, relation | Ledger core is smaller, governance still required. |
| Path to surface | 10 stages; 8–9 translations | 5 stages; 2 translations (Spike 13) | Projection machinery, not evidence safeguards, was reduced. |
| Section handling | 20-section compiler | deterministic route + progressive card | Compiler is not required before product learning. |
| Meaning preservation | Typed graph | 12/12 retained claims, scope/time, IDs/roles | Holds for proposition-compatible corpus only. |
| Missingness | dedicated coverage | 5/5 explicit coverage states | Keep separate from claims. |
| Review | 16 units | 16 units | Thinner surface does not reduce semantic review. |
| Query | requires read model | 6/6 bounded cited/abstaining simulations | Query reads ledger; it must not replace it. |
| Domain detail | implicit in specialised model | optional qualifier on 5/16 stress candidates | Generic envelope needs narrow escape hatches. |

## Product architecture decision

Adopt a durable proposition ledger as the product read model and let deterministic routes compile a progressive card. Keep domain contracts for relationships, measures/outcomes, conduct and any qualifier that materially changes assertion meaning. Treat the full 20-section dossier as an optional investigative projection, not the prerequisite for a useful public card.

This is not an instruction to delete provenance, source authority, candidate status, promotion, coverage or corrections. It is a decision to stop treating a fixed card compiler as their architectural centre.
